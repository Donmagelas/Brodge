实际限制：

- 未加载会话的 owner discovery 超时现在会触发限频的 Desktop 深链接恢复；完整冷启动真实验收仍不足，不能声称全程无人值守稳定。
- 当前 Brodge 把异步问题有效期绑定在原回合；回合结束后引用题目会提示失效，普通新消息仍可在同一会话继续。早期两次测试因换版／未及时回答而结束，未算成功；后两次原回合内选择和自填均成功。问题结束后给明确提示。
- Desktop 的 follower-steer 不接受外部 expectedTurnId，内部可能在并发回合变化时重新选择活跃回合；Brodge 在提交前核对原问题，并只接受原 turn 的回答证据，不重试未知提交，但无法提供 Desktop 同时切换回合时的原子隔离。需要上游有条件提交接口才能完全消除这类竞态。
- 旧 source 的未提交精简删除保留，未回滚。复用现有 inbox/jobs/outbox/questions，仅增加必要媒体字段与入口会话关联；未增加其他 IM、服务商、技能或用户定时任务。

## 目标与方案引用

把现有 cc-connect 二开的 Desktop／飞书桥接扩展为 Brodge：仅创建者使用、多入口及入口内多会话、无项目自动新建和 `/new`、图片／文件收发、表情回应与完整最终答案、失败恢复和原生弹窗回答，以及 Mac 双击启动和 Web 关闭。

新建固定为 Codex Desktop 的无项目普通会话。Web 复用现有页面补功能，视觉与布局改版不在本计划中。微信、Windows、多人授权、远程审批、服务商、技能管理和定时任务不在本阶段。

计划覆盖全部已讨论 ticket；“用户功能已经定义”“本机接口已找到”“实现和模拟测试通过”“真实联调通过”分别记录。缺失的 Desktop 接入口不能由模拟测试或降级提示代替完成。

## 全局约束

- 以现有 Desktop 进程、登录、API／网关、模型和权限设置为准；完全访问是用户已经设置的前提。不得读取或复制 Codex auth、改变网关、改安装包、改用 CLI 或独立 app-server。
- 保留现有飞书应用、创建者和私聊配对、绑定、消息历史与配置。改名和状态结构迁移使用兼容读取与可恢复迁移，不清空 `.state` 或重建机器人来简化实现。
- 依赖继续为 `cmd → config/core/agent/platform`，具体 adapter 只依赖 `core`。扩展现有来源、绑定、消息入口和 outbox，不新增任务系统、附件服务、模型控制层或常驻 supervisor。
- 入口先认证并持久登记再处理；恢复只核对确切创建／回合／问题证据，不盲目重建会话、重复运行模型或重复回答。回复使用原消息来源及固定发送标识。
- 管理接口仅 loopback，保留认证。自动打开 Web 使用一次性登录衔接，不把长期密钥放 URL，也不输出凭据或原始 SDK 消息日志。
- 不覆盖既有未提交改动。实现期间核对原配置和私有文件完整性时仅记录一致／不同，不打印内容。修改当前运行版本前保存可恢复副本，保留原状态；不同时启动两份接收同一应用事件但使用不同状态目录的程序。
- 测试采用仓库既有真实 SQLite、模拟 Desktop Unix socket、飞书官方 SDK 的本机 HTTP／事件测试边界。真实发送和会话写入仅使用用户明确授权的测试入口；不得使用当前开发会话。
- 每步验证通过后推进依赖步骤；新失败或新改动才重复相关检查。最终运行一次完整验证，不因局部通过声称全部闭环。

- **依赖：**无。部分真实能力证明需后续授权测试；不拿本次 Codex 工具里的 `create_thread` 当产品常驻创建接口。没有入口时先记录事实，停止对应依赖功能，继续可独立步骤；改变既定接入边界需返回方案讨论。
- **验证方法：**授权的只读 preflight 与原会话快照核对；模拟接口契约覆盖版本、owner、final phase、附件形状、问题类型与请求 ID。完整创建最终须证明无项目会话在 Desktop 可见、能取得 owner、可继续对话并沿用适用设置。原生答案须证明原请求实际被接受。此步骤不因源码存在而标成真实验证通过。

### S1. 创建者、多入口与入口内会话切换

- **预期结果：**正式转发复用扫码记录并经配对核对的创建者身份；只接受本人私聊和允许群中本人 @。每个入口持久保存关联会话集合及一个当前绑定。`/bind` 导入已明确授权的会话，`/list`／`/switch` 限本入口，`/current` 查看当前；不同群与私聊隔离。
- **改动区域：**`platform/feishu/setup.go`、`desktop.go`、启动装配处 `cmd/brodge/plugin_platform_feishu.go`；`core/interfaces.go`／`message.go` 的必要来源字段；`agent/codexdesktop/store.go`、`conversation.go`、`agent.go`；现有绑定 API 和 `web/src/pages/Projects/DesktopConversation.tsx`。沿用现有来源键和数据库做最小扩展，为平台／连接区分增加兼容字段。迁移同步核对绑定、inbox、jobs 及保存的回复来源，不能只改新消息键。
- **依赖：**不依赖 S0 的创建接口；使用明确授权的已有会话即可完成。与后续媒体／命令数据扩展共用结构时顺序集成，避免各自新增一套来源或绑定模型。
- **验证方法：**既有绑定迁移后 revision 与来源保持；重复启动不重复登记。非创建者、未允许群、缺 @ 拒绝进入执行。本人私聊／群 A／群 B 各自 list 与 switch；跨入口 ID 不能直接切换。快速 bind／switch 后正文仍按入站顺序选会话；切换不重定向已接受消息和旧结果。Web 仍需认证，仅显示安全字段。

### S2. 无项目自动新建与 `/new`

- **预期结果：**共用一条创建／登记／绑定逻辑。无绑定正文自动创建原生无项目会话，并把原消息作为首轮；`/new` 创建空会话加入本入口列表并切换。旧会话保留。成功新建的 ID 持久登记为可接入会话，不要求每次手改静态 `allowed_threads`；空授权列表可用于新安装，但不开放所有已有 Desktop 会话。
- **改动区域：**`agent/codexdesktop/ipc.go`、`agent.go`、`conversation.go`、`store.go`、`config/config.go`，及最小能力／错误状态提示。通过原生 projectless 语义解析位置和设置，不传开发目录、不绑定项目、不创建 worktree。创建 intent、确定结果和绑定变化复用持久入口／数据库，不另建生命周期服务。
- **依赖：**S1 的入口列表，以及 S0 的完整创建入口及可核对证据。若当前 Desktop 不提供满足约束的创建接口，本 ticket 保留技术阻塞；不能以提示用户手动创建算完成。
- **验证方法：**无绑定首条文字只创建一次、原文成为首轮；`/new` 后 list／switch 继续旧暗号；连续两条、重复事件、创建前／创建成功未落绑定时崩溃、未知创建结果、重启和离线均不重复创建。失败不覆盖原绑定。真实证明新会话属于 Desktop 无项目普通会话，能在 Desktop／IM 继续同一会话。

### S3. 表情回应、最终答案与基础异常提示

- **预期结果：**有效请求持久接收后对原消息加机器人表情；移除正常“已收到／正在处理”文字。仅在原回合结束后发送 final，长任务也不播报进度。表情失败不阻塞执行／结果。区分模型 failed／interrupted、Desktop 暂时断连、待确认提交和飞书交付异常，保留原状态及恢复依据。
- **改动区域：**`platform/feishu/desktop.go` 的官方 reaction API；`core/interfaces.go` 的必要消息动作边界；`agent/codexdesktop/state.go`、`agent.go`、`conversation.go`、`store.go`；`core/i18n.go` 与现有 Web 状态。复用 outbox 的消息动作和持久回执，表情与结果的阻塞规则分开。默认选一个含义明确且官方支持的“已收到”表情，不增加选择器。
- **依赖：**S0 的 final／terminal 数据识别。未确认 final 标记时不能用最后一条过程文字冒充最终答案。已有绑定即可验收，不依赖 S2 新建。
- **验证方法：**同时存在 commentary 和 final 时只发 final；短任务、长任务只有原消息表情和终止后答案。重复事件、reaction 失败／未知、重启不产生重复回合。模拟模型断流、桥接断连而模型继续完成、未知 start ACK；不把断连误报失败或重新提交。失败明确提示未完成，用户明确继续才进入同会话新一轮。飞书全链路离线时 Web 显示实际状态，不声称已发通知。

### S4. 飞书图片与文件进入 Desktop

- **预期结果：**接受官方 image／file 和可支持的图文消息资源，保存原消息资源信息后下载私有缓存，再把文字与全部附件交给同一 Desktop 回合。图片是真实图像输入；文件保留名称／类型／原始字节／本地路径，由 Desktop 工具读取。纯媒体私聊正常受理；同消息多附件一轮，不同消息不按时间合并。
- **改动区域：**`platform/feishu/desktop.go` 的内容解析与官方资源获取；`core/message.go`／`interfaces.go` 的必要媒体字段；`agent/codexdesktop/store.go`、`conversation.go`、`agent.go` 的持久资源状态和 turn 输入。缓存位置纳入现有 state，落盘后再确认可提交；不在事件处理器里阻塞下载或把附件变成二进制 prompt。
- **依赖：**S1 的来源验证与 S0 的图片／文件上下文输入契约；与 S2 联合时再覆盖无绑定纯媒体首轮。下载和持久入口可独立验收，不能代替 Desktop 实际读取。
- **验证方法：**SDK 本机资源接口核对 message ID、resource key、字节、中文文件名、多个资源；失败／失效／缺 key／超限／部分下载失败不静默只传文字。未知格式给明确提示。Unix socket 测试核对真实图片类型与文件上下文、重启保留缓存。真实图片内容题和小附件内容题验证实际读取；群媒体 @／引用形式按实际事件核对，无法取得资源不能算支持。

### S5. 完整最终答案的格式与超长投递

- **预期结果：**保存完整 final 后转换飞书支持的富文本／卡片，保留段落、列表、代码和链接；按消息类型实际限制分段，不重写／总结。复杂内容使用可读文本、静态呈现或原内容附件回退；Desktop 专属 directive 转为可理解的信息，不把内部标签裸露给用户。发送按原内容顺序持久排队。
- **改动区域：**`agent/codexdesktop/state.go`／`store.go` 的完整答案和顺序记录；飞书 adapter 的格式转换／限额处理；必要的 core 消息表示。格式转换位置遵循依赖方向，core 不导入飞书。明确区分段落／代码／媒体引用，不从任意本机路径猜附件。使用现有出站回执与恢复逻辑，替换一刀切的 3500 字符分段策略。
- **依赖：**S3 的最终答案提取和消息动作。先完成 S5 的通用顺序记录和正文转换，S6 再扩展媒体投递；需要文件回退的内容在 S6 完成后联合验收，避免两个步骤互相等待。
- **验证方法：**中文、emoji、Markdown、代码围栏、链接、表格、公式、超长段落和包含特殊字符的消息编码边界；分段拼回后信息一致，没有截断或遗漏，消息大小含编码开销。前段未知时后段不抢先；重启／重试只补未确认部分，不重新运行模型。真实飞书检查桌面和手机可读性；可支持格式与回退形式如实记录。

### S6. 图片／文件产物的原生回复

- **预期结果：**从本轮明确的 Desktop 产物／附件引用或明确发送动作获取文件，保存副本和校验值，调用官方图片／文件上传，再回原消息。正常产物在本轮终止后与正文按序交付，失败状态不能变成成功。上传 key、快照和发送回执持久保存，避免重试发送被修改后的文件。
- **改动区域：**`agent/codexdesktop/state.go`、`agent.go`、`store.go` 的产物解析／待投递记录；core 必要出站媒体结构；飞书 adapter 官方 upload／reply。只读参考 Bro 的快照和原来源流程，按 Go 实现复用。缓存清理只处理不再被待提交／待投递记录使用的文件，暂不做用户管理模块。
- **依赖：**S0 的可信产物出口、S3 的终止／状态语义、S5 的统一有序投递记录。图片／文件上传可先用明确指定的本机测试产物验证，但不能据此宣称 Codex 自动交付链路完成。若必须另加发送工具，先核实能接入现有 Desktop 且不改全局配置／来源边界；需要改变方案时先返回讨论。
- **验证方法：**官方 SDK 本机 HTTP 测试覆盖字节、文件名、原 message／chat、上传 key 复用、固定发送标识、重复调用、文件变更、上传失败、发送未知和重启。真实发回图片及文件，回查原生消息类型、原聊天及下载字节。不能扫描目录自动发文件，不能用飞书桌面模拟代替。

### S7. 原生选择与自填答案闭环

- **预期结果：**对用户统一为一种“Codex 等待选择／回答”。飞书题目附选项与说明，创建者引用后回复编号／选项名或自由文字；按原问题类型转换并提交到原请求，当前回合继续。多题逐题收集，旧问题失效不回答下一题。少见也必须验收，不以 Desktop 手动处理代替功能完成。
- **改动区域：**`agent/codexdesktop/state.go`、`agent.go`、`conversation.go`、`ipc.go`、`store.go`；`core/i18n.go` 与飞书可引用的题目消息。复用现有 questions 记录，保存 question／request 类型和选项映射；普通问答与 picker 内部各用实际提交协议，不新增两个用户功能。只在真实支持后启用远程答案能力。
- **依赖：**S1 的入口／身份、S3 的等待与终止语义、S0 的原生答案入口。普通 `requestUserInput` 先完整验证；picker 入口缺失时保持该项未完成，不发送普通 followup 伪装原生答案。群回复必须可核对创建者、原问题和当前触发条件。
- **验证方法：**编号与真实值映射、自由答案、单题／多题、相同题目不同 ID、切换后引用旧问题、重复答复、超时／取消／原回合结束、Desktop 抢先回答、提交 ACK 丢失和重启。只有确切答案证据及原请求关闭才确认已回答。真实验证选项与自填答案两条路径均在原回合继续；遇到其他实际题型补对应测试，未知请求明确保留缺口。

### S8. 统一 Brodge 名称并保留兼容数据

- **预期结果：**应用、Web、发布二进制、日志、构建入口和项目文案统一为 Brodge。保留上游出处及许可证信息；必要 Go module／imports、包名及目录变化一次同步。旧配置／状态仍能读取，迁移后继续原配对和绑定。
- **改动区域：**`cmd/brodge` 的必要目录／名字、`Makefile`、CI、`web/package.json`／锁文件、`web/index.html`、文案及 i18n、Go module／imports、`.gitignore`、README／贡献文档／当前运行说明。私有配置文件不批量替换名字，运行数据路径使用兼容映射或可恢复迁移。
- **依赖：**不依赖新建／媒体的接口；放在功能结构与路径基本稳定后一次完成，避免前序计划的路径多次改动。S9 打包依赖最终名称。该步骤不擅自换掉正在运行的旧服务。
- **验证方法：**构建／测试／CI 引用新的真实入口；针对保留源码搜索旧产品名，区分应保留的上游归属和应更名的显示。用旧格式配置与复制的状态验证连续启动和原绑定恢复，输出一致性结果，不泄露凭据。产物名与 Web 标题一致。

### S9. Mac 双击、自动开 Web 与页面关闭

- **预期结果：**Brodge.app 内含一个核心程序和内嵌 Web。双击后创建或复用一个本机后台实例，待 Web 就绪自动开默认浏览器；无终端操作依赖。现有配置可兼容指定，新安装仅生成 Brodge 自己的私有配置／状态，不读取 Codex auth；配置缺失时可打开管理页完成已有扫码／配对流程，而不是直接进程报错退出。
- **改动区域：**更名后的 cmd 启动入口、`config/config.go`、`core/management.go`／`engine.go`、飞书生命周期与现有 setup 装配、Web auth／API／最小关闭按钮、Mac 打包脚本和必要 `.app` 元数据。默认持久位置采用用户应用数据位置，与 Finder cwd 脱钩；对当前已存在配置／数据保留显式兼容入口。复用核心程序的启动和服务模式，不引入 Electron、WebView 或登录自启动服务。
- **依赖：**S8 命名；最小启动／退出可独立于 Desktop 新建入口测试。完整功能包需集成 S1–S7。setup 到已配对连接的启用衔接在现有管理面完成，避免最终用户仍必须编辑 TOML 或在终端导出密钥才能用扫码创建的应用。
- **验证方法：**从 Finder 启动、重复双击、已有实例复用、服务就绪等待、端口占用／未知实例／配置错误有明确状态，不能打开别的本机服务冒充 Brodge。一次性登录不可重复使用，管理 API 仍认证。关闭按钮先请求有序退出，验证停止新接收、SDK／worker／配对子进程结束、端口和文件锁释放、核心进程退出；不能只用 `window.close()` 代替退出。关不了标签显示已退出，多页一致，直接关标签后台继续。Desktop 回合不中止，重新打开核对原回合并恢复待投递结果，不重跑。没有前端 dev server 的真实包启动／退出通过，保留数据与 Codex 配置。
