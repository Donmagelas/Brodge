# Brodge：IM 会话、回复与交付方案

更新：2026-10-10。项目名称为 **Brodge**。暂时只有应用创建者可用；每个 IM 入口保留关联过的 Codex 会话列表及一个当前绑定。用户已选定无绑定时通过 Desktop 界面自动创建并绑定，也可提前手动绑定、以后修改绑定。仅 `/new` 暂缓，保留 `/bind`、`/list`、`/switch`、`/current` 和 Web 绑定管理，方便在已有会话之间切换工作。新建使用 Codex 无项目普通会话，Web 外观改版后置。文字界面创建、持久接续和入口管理已真实验证；群图文与引用 PDF／Word／Excel 收发、首条图片自动新建亦已通过；首条 PDF 经重试完成新建和输入，网关 401 后换绑，实际读取与原文件回传补测通过，详见 implementation.md。

当前范围补充（2026-10-10）：手机端专项验收、其他弹窗协议扩展、标题／表格／公式进一步转换按用户要求暂不推进，保留现有可用实现。模型回合结束后，普通新消息在原会话开启新一轮并保留历史；引用已结束的题目仍提示失效。已有绑定的真实 Desktop 重启恢复已验收，文字界面首次创建已真实通过；具体证据与边界见实施记录。

## 问题与目标

保留“IM 连接 → 入口绑定 → 本机 Codex Desktop 会话”的结构，让创建者能够：

- 在飞书私聊和不同群聊分别使用会话。
- 在入口没有绑定时自动新建 Desktop 会话，直接处理第一条消息。
- 可以通过 Web 或 `/bind` 提前绑定已有会话，并在之后修改绑定。
- 通过 `/list` 查看本入口关联的会话，`/switch` 切换工作会话，`/current` 确认当前会话。
- 收发图片和附件文件。
- 飞书收到有效请求后先对原消息添加表情回应，正常处理期间保持安静，结束后只发送最终答案，保留可呈现的文字、格式、图片和附件。

桥接器负责连接、绑定和消息交付。实际对话、工具、模型、技能和权限继续由现有 Codex Desktop 管理。

## 范围与非目标

本阶段面向一个飞书应用及其创建者，支持创建者私聊和任何已加入机器人的群聊，不设群白名单。群里需要创建者真实 @ 机器人；其他人即使 @ 也不触发。

微信等 IM 只保留协议和绑定键的兼容边界，本阶段不接入。暂不做多人授权、角色管理、共享会话、项目选择向导、额外聊天界面、服务商管理、技能管理、定时任务或远程权限审批。

仅 `/new` 暂缓，不作为本版入口、帮助说明或验收要求。入口内会话列表、切换和当前会话查询保留；列表收录该入口自动创建或明确绑定过的会话，不枚举所有 Desktop 会话。多个入口各自独立，不自动清除已有 Desktop 会话、绑定或历史消息。

Web 只承载连接、创建者身份、入口及会话绑定和必要状态；新建固定为 Codex 无项目普通会话，不增加项目／工作目录选择器。用户明确先完成功能再考虑外观，本阶段复用现有布局，仅补必要功能入口和状态。

## 约束与已知事实

下面保留实施前基线；已完成能力与真实验证以同目录 `implementation.md` 为准，后续行为以本文最新方案为准。

- 保留现有 Desktop 登录、模型、API／网关和权限设置。不读取或复制 Codex auth，不切换 CLI，不启动独立 app-server，不修改安装包来实现桥接。
- 用户确认本阶段以使用者已在 Codex 开启完全访问权限为前提。Brodge 不提供权限模式选择、远程批准、审批卡片或审批专用跳转流程，也不替用户修改 Desktop 权限设置；需求问答和选择弹窗仍需用户回答。
- 现有 `bindings` 支持多个入口，但每个入口只有一个当前 `thread`。因此“多个入口”已有基础，“一个入口保留多个会话并切换”仍需扩展。
- 飞书扫码创建记录已有创建者 `OwnerOpenID`，私聊配对也验证该身份。正式消息路径目前仍使用配置允许名单，尚未统一强制为创建者规则。
- 当时 `/list` 列全局 `allowed_threads`，`/switch` 可以选择全局允许的会话。后续已实现入口内列表／切换，本版继续保留，具体执行记录见 `implementation.md`。
- 已有会话的真实飞书私聊文字往返与追问已验证。当前 `/new`、图片和文件均未接通。
- 本机 Desktop 源码有完整创建流程，但当前 follower IPC 接入尚未找到可用的完整创建入口。内部 `thread/start` 不能单独证明会话能完整出现在 Desktop、取得 owner 并沿用设置。
- Desktop 输入协议有图片相关类型，当前桥接提交仅有文字；结果解析也仅接收助手文字。媒体输入和产物出口仍需验证。
- Bro 当前源码已有官方飞书资源下载、文件上传和原消息回复流程，可参考流程，不引入它的其他框架。
- 当前收到正文会排队发送“已收到，等待 Codex 处理。”，观察到回合进行中时另发一次“Codex 正在处理。”，终止后发送结果。当前没有表情回应代码，也不流式转发模型文字。
- 当前结果解析把本轮所有 `agentMessage.text` 拼接起来，不区分过程说明与最终答案；飞书使用普通 `text` 消息，超过 3500 个 Unicode 字符按顺序分段。不能声称当前已经完整呈现最终答案格式。
- 本机 Desktop 安装包存在 `phase: final_answer` 与 `commentary` 区分；需验证当前桥接读取的回合数据是否稳定携带该字段，再据此筛选最终答案。
- 当前 `make build` 先构建 Web，再输出 `cc-connect` Go 二进制；Web 静态资源嵌入二进制。同一进程启动 Desktop adapter、飞书连接和 loopback Web 管理。没有后台服务安装或登录自启动入口，当前仅验证 macOS。

## 候选方案与权衡

会话管理复用现有入口、绑定和 `binding_threads` 记录，每个入口保留关联会话列表和一个当前绑定。`/bind` 将已有会话加入本入口并设为当前，`/switch` 在已关联会话之间切换，`/list` 和 `/current` 提供查看；保留现有消息队列与恢复逻辑，不新增会话管理服务。

首次新建采用 Desktop 界面辅助创建：打开无项目新聊天页，填入并发送原消息，取得确切会话与首轮信息，再交给现有 IPC 跟随和回传。UI 操作仅用于首次创建，已有绑定继续走现有桥接。CLI 或独立 app-server 会改变现有接入和配置边界，不采用。

2026-10-10 补充验证：当前 Mac Desktop 内置 `create_thread` 的原生管道已定位，但独立进程的只读 `tools/list` 请求被调用方校验以 `untrusted-process-ancestry` 拒绝。该通道不能作为 Brodge 的创建入口；详见同目录实施记录。用户随后选定界面辅助创建，仅 `/new` 暂缓，不实现空会话或延迟 `/new`；已有会话的列表、切换与查询保留。

媒体传输复用现有持久入口和出站记录。发出产物时优先使用 Desktop 明确的附件／产物引用；如果不足，再研究明确的发送工具。不扫描工作目录自动发送，也不把任意文字路径直接当成发送指令。

## 最终方案

### 已收敛的 ticket 范围

以下是当前讨论的功能清单，不是执行步骤或新增的任务管理功能。新建会话类型已确定为 Codex 无项目普通会话；技术入口能否接通与产品需求是否清楚分别记录。

| Ticket | 预期行为 |
| --- | --- |
| 名称统一 | 应用、Web、发布和相关标识统一为 Brodge，保留原数据与上游归属 |
| 创建者与多入口 | 只允许创建者；私聊与不同群的 @ 各自对应入口，为未来 IM 保留连接区分 |
| 会话列表与当前绑定 | 每个入口保留关联会话和一个当前绑定，支持提前手动绑定及以后换绑；保留 `/bind`、`/list`、`/switch`、`/current` 和 Web 管理 |
| 首次新建与自动绑定 | 无绑定时通过 Desktop 界面创建无项目会话，原消息作为首轮，取得 ID 后加入入口列表并自动绑定；仅 `/new` 暂缓 |
| 图片收发 | 真实图片输入进入 Desktop；明确图片产物以飞书原生图片回复 |
| 附件收发 | 原文件交付 Desktop；明确文件产物以飞书原生附件回复 |
| 回应与最终答案 | 原消息表情回应，正常处理期间安静，结束后只交付 final，长任务同样处理 |
| 格式与完整交付 | 保留最终内容，转换可支持格式；超长内容分段、媒体原生发送，顺序和恢复不丢内容 |
| 异常与恢复 | 区分模型断流、Desktop 断连和飞书投递失败，提示真实状态，不盲目重跑 |
| 原生弹窗回答 | 飞书题目与选项／自填答案提交回原请求，原回合继续；低频仍必须验收 |
| 双击启动与关闭 | Mac Brodge.app 启动后台并打开普通浏览器；页面按钮退出后台，标签关不了显示已退出 |

Web 随上述功能提供必要的连接、绑定、配置和状态入口；整体视觉与布局大改在功能完成后另行讨论，不纳入本阶段。每项实现都保留现有 Desktop 配置、飞书配对和持久消息，验证重启与正常对话回归。

### 项目名称

对外名称确定为 Brodge。程序名、发布文件、Web 标题与产品文案、日志标识、构建命令、包名和本项目文档统一调整；代码目录、Go module／imports 和启动标识按必要范围同步处理。上游出处和许可证归属仍如实保留。配置路径及既有数据目录用兼容读取或明确迁移衔接，不因改名重置已配对凭据、绑定和消息记录。按用户要求，统一实施前不改当前程序。

### 创建者身份与入口

飞书只接受扫码创建时记录并经配对核对的创建者。创建者身份缺失或不匹配时不开启转发；不把最先发消息的人自动当作创建者。沿用已配对身份，不要求重新配对现有连接。

私聊只接受创建者。群聊同时满足：机器人已在群内、发送人是创建者、消息真实 @ 机器人。权限只认创建者，不设置群白名单；旧配置中的 `allow_chat` 不再限制可用群。群身份仍参与会话绑定键，确保不同群各自使用独立会话。

入口键区分具体 IM 连接、聊天和发送人。当前例子：

| 入口 | 关联会话 | 当前绑定 |
| --- | --- | --- |
| 创建者飞书私聊 | T1、T2 | T2 |
| 创建者在群 A @ 机器人 | T3、T4 | T3 |
| 创建者在群 B @ 机器人 | T5 | T5 |
| 将来接入的微信私聊 | 独立列表，后续实现 | 独立绑定 |

同一个人也不会默认跨私聊、群聊或 IM 共享上下文。群聊结果对群成员可见，创建者身份限制的是谁能触发，不是群内谁能看回复。会话分开也不提供本机文件权限隔离。

### 会话列表、切换与手动绑定

每个入口保留自动创建或手动绑定过的会话，以及一个当前会话。创建者可以在第一条业务消息前手动绑定已有会话，也可以在自动绑定后加入另一个已有会话，并在这些会话间切换工作。换绑或切换不删除旧会话或历史，无需额外任务编号。

- `/bind codex://threads/ID`：将已有会话加入当前入口的列表，并设为当前绑定，仍校验创建者、来源与 Desktop 可接入性。
- `/list`：列出本入口关联的会话，并标记当前会话。
- `/switch ID`：切换到本入口列表中的已有会话，之后的普通消息使用该会话的上下文；不创建新会话，不隐式导入其他入口的会话。
- `/current`：显示当前绑定的会话；没有绑定时明确提示，不触发创建。
- Web：显示各入口的关联会话及当前绑定，允许提前绑定、加入已有会话和后续修改当前绑定。
- `/new`：暂缓，不展示在帮助中，不执行创建，也不作为普通正文发送给模型。

新建的确切会话 ID 持久登记为本入口可接入会话，并加入入口列表，不要求用户每次修改静态 `allowed_threads`。保留已有绑定、`binding_threads` 和历史授权数据，不做破坏性存储清理。Web 预绑定使用已经认证的配对／入口信息，不要求先从飞书发送 `/current`；`/current` 是可选查询命令。

### Web 解绑与可读会话信息（2026-10-12）

每条关联会话提供“解除绑定”。仅移除选定入口与会话的关系；删除非当前关联不改变当前绑定，删除当前关联后显示未绑定，不自动改选其他关联。Desktop 会话、配对及历史消息保留，未绑定后的新正文仍按既有规则自动创建；用户也可先手动绑定。按用户任务已结束的场景做简单解除，不增加任务取消或等待功能。

绑定信息显示“私聊 · 我”或“群名 · 我”；只允许创建者的阶段不为获取姓名增加权限。Codex 优先显示实际会话名称，未命名时以清理后的首条文字作为标题。一个入口有关联多个会话时，在每条下方显示该 Codex 会话最近一条用户提问的预览，并附 1、2、3 编号及当前标记。名称、预览、编号不参与身份或路由，完整 ID 保留在详情中。所有名称与历史读取均只读；不能为了刷新页面加载／导航 Desktop 会话或触发模型请求。

### 无绑定时通过 Desktop 界面自动创建

流程：验证来源并持久接收 → 检查入口绑定 → 无绑定时打开无项目新聊天页 → 填入并发送原消息 → 取得这次新建的确切会话 ID 和首轮证据 → 保存绑定 → 使用现有 IPC 读取该轮结果并回传。

原消息直接成为首轮，包含随消息收到的图片／文件；不要求用户重发，不发占位请求，也不能在界面已经发送后再通过 IPC 重复提交首轮。已有绑定时普通消息直接进入当前会话，不启动创建操作。

新会话使用 Codex Desktop 原生的无项目普通会话，不绑定仓库、不创建 worktree，也不默认采用 Brodge 的开发目录。工作目录与适用的 Desktop 设置通过原生创建流程解析，不由 Brodge 另行发明“无项目”的目录语义。已有会话继续使用自己的工作目录和设置。

同一入口快速连续发送时按入站顺序处理，只创建一次；创建失败不覆盖旧绑定，原消息仍保留。创建结果不确定时先核对创建证据，不能盲目重复创建。Desktop 离线时显式告知并保留消息，不切换执行端。

创建由独立运行的 Brodge 执行；开发会话中的 Computer Use 成功不能代替产品验证。使用目标窗口及可识别的输入、发送控件，确认无项目和新聊天状态；不能向不明焦点粘贴内容或凭“最近一个会话”猜 ID。需要 macOS 辅助功能权限时由用户授予，不修改 Desktop 安装或绕过其身份校验。用户操作使目标状态改变、界面不可识别、权限不足或结果不确定时停止 UI 动作并报告明确状态。多个入口的首次创建串行使用界面，普通已绑定会话继续复用现有处理链路。

手动换绑或 `/switch` 后新消息进入选定会话，已经接受的旧消息仍属于旧会话，结果回复原消息。明确回复已经登记的旧机器人结果时仍可继续对应旧会话；这不自动改变当前绑定。

### 图片和文件输入

先校验来源并持久登记消息及资源信息，再下载官方消息资源到本机受控缓存。下载失败明确反馈，不把缺失附件当成已读取，也不悄悄只提交剩余文字。

- 图片以真正的图片输入连同文字进入同一 Desktop 回合；不只传 `image_key` 或一个文字路径。需核实所用模型支持图片，并验证 Desktop 实际收到图像。
- 文件保留文件名、类型和本地路径，通过 Desktop 可读取的附件上下文交付；不把二进制塞进文字提示。解析 PDF／Word／Excel 等内容由 Codex 的工具和技能承担。
- 同一消息的多张图片／多个附件为同一轮。单独发送的不同消息不按时间窗口自动合并。
- 私聊允许纯图片／文件消息；无文字时以“查看附件”等最小上下文提交。群聊媒体仍需创建者真实 @ 触发，实际支持的图文／引用形式待核实。

### 图片和文件输出

在本轮请求中明确选定要发送的产物，从可信的附件／产物引用或明确发送动作获取文件，再由现有出站流程交付。

保存文件副本与内容校验值，上传飞书，作为原聊天中的原生图片或文件回复；重试沿用已选定内容、上传结果和固定消息标识。收件目标由原请求确定，不让模型猜联系人或群。

只有平台返回发送回执才报告已发送；上传失败或发送结果不确定时显示真实状态，不改用飞书桌面模拟。具体大小／格式限制在接入时按官方接口及本机资源约束确定，不沿用未经核对的固定值。

### 飞书回应与最终答案

用户确认只发最终答案，并尽可能保留文字、格式、图片和附件。正常流程为：验证来源并持久接收 → 对原消息添加一个机器人表情回应 → 提交或等待 Desktop 执行 → 本轮结束后发送最终答案及明确关联的产物。

表情表示“已收到”，不表示成功或已经开始执行。短任务、长任务使用同一流程，不再发送普通“已收到／正在处理”文字，不流式刷新、不周期播报进度。表情通过官方 `messageReaction` API 添加，机器人身份显示由飞书决定，不能显示为用户本人。默认使用用户选择的屈臂表情 `MUSCLE`，已在官方文档及真实测试消息上核实。

表情失败不阻止执行或最终结果交付，也不能因重试创建重复回合；持久保存回应状态，按原消息和机器人回应核对重复。失败、输入缺失或需要用户回答时仍及时提示，不能因为等待“完整结果”而让用户无提示地卡住。完全访问是使用前提，本阶段不设计权限审批交互。

最终答案按原生 final phase 提取，不把 commentary、工具日志或隐含内部信息合入正文；未知协议或缺失 final 证据时要显式处理，不能盲目把最后一条过程消息当作最终答案。原生失败／中断保持真实状态，不改写为成功。

“完成后整体回复”指内容收齐后再开始交付，不保证所有内容只占一个飞书消息。超出平台大小限制时按自然内容边界拆分并保持顺序，图片和文件以原生媒体消息交付；不裁掉超长内容、不用模型重新总结代替原答案。

### 完整结果的分批交付

1. 等待确切的桥接回合终止，从 final phase 提取最终正文和明确关联的图片／文件引用。先保存完整结果，不把生成中的增量文字发送到飞书。若模型过程中请求发送文件，先确定并保存文件副本，正常结果的交付同样等本轮结束后进行。
2. 解析正文结构，转换成飞书支持的段落、列表、链接和代码等内容，并把明确媒体引用变成对应的原生消息。按原文顺序生成一组待发送记录；不再请求模型缩写或重排。
3. 根据实际消息格式的官方限制计算大小，包含 JSON／转义等开销，优先在段落和完整结构之间切分。超长代码块切开时补齐每段围栏；超大的表格／复杂结构用保留原内容的附件或静态呈现回退。不能用当前固定 3500 字符切片代替所有格式的限额计算。
4. 同一结果按序发送，例如正文第一段 → 正文第二段 → 图片 → 附件。每段记录固定内容、序号、来源和发送标识；上传返回的媒体 key 也持久保留。前一段发送结果不确定时核对后再继续，避免后段先出现。
5. 发送失败时重投已有的待发送记录，已经确认发送的内容不重发，不重新运行 Codex 来“恢复发送”。仅能获得有限时间的平台幂等保证；证据不足时显示待核对，不宣称绝对不会重复。

表情状态独立于结果投递的先后约束，不能因表情失败阻塞最终答案。正常结果、错误提醒和原生问题都复用现有 inbox／outbox，不新增独立投递服务。

### 失败、断连和原生交互

异常不能全部视为模型失败：

| 情况 | 飞书处理 | 恢复行为 |
| --- | --- | --- |
| 模型明确断流／回合 failed 或 interrupted | 提示本轮未完成，保留原会话；不把残缺输出作为完整最终答案 | 不自动重跑。用户明确要求继续后，在同会话发新一轮，让 Codex 结合现有记录继续；不保证恢复同一个流 |
| Brodge 与 Desktop 的连接断开，但尚不知回合结局 | 持续中断时提示连接状态待确认，不直接报任务失败 | 重连后只读取原回合证据；完成就交付结果，仍在执行就继续等待。不能盲目重新提交原请求 |
| 模型已完成，飞书上传／发送失败 | Web 保留真实投递状态；在仍可发消息的情况下提示交付异常 | 重投保存的结果／媒体，不重新运行模型。飞书全链路不可用时无法通过同一链路即时通知 |
| 用户所见的原生选择／自填答案弹窗 | 统一提前转发题目、选项和必要说明，等待创建者选择或填写 | 按原请求类型提交答案，继续当前回合；部分底层通道尚待验证，不能因此取消该需求 |
| 密码／登录／敏感表单或未知交互 | 不转发敏感字段，提示 Desktop 处理 | 不猜协议、默认值或答案，不绕过现有设置 |

普通原生问答建议第一版使用可引用的题目消息和编号选项，创建者引用该问题后发送编号、选项名或自由文字；选项说明也应保留。编号在桥接端映射为真实选项值，不把“1”直接当任意答案。一次请求含多题时逐题收集，全部收齐后提交原请求；只支持已验证的题型。

答案绑定到原入口、会话、回合、request 和 question。群里仍验证创建者和触发条件。提交前重新核对请求有效；若用户已经在 Desktop 回答、取消或回合结束，则拒绝旧回复并说明问题已失效，不用旧答案回答下一题。提交回执只表示发送成功，还需读取原请求消失及答案记录证据，才能确认已经回答。未知结果不重复提交。

内部协议差异不增加用户功能。当前已真实验证异步选项／自填问题；同步 requestUserInput 只有模拟测试证据，其他 picker 未接入。按用户最新要求，暂不继续扩展这些协议。

普通助手文字提问不一定是原生弹窗：没有原生待答请求时，用户回复就是同会话的新一轮；有原生请求时不能以普通追问代替答案。本机已启用并真实验证常用异步问答。模型回合结束后普通消息仍在同一会话继续，当前不增加专门跨回合回答机制。

### 最终答案的呈现边界

目标是保留最终答案的信息，不能承诺复制 Codex Desktop 的完整界面。

- 普通文字、段落、基本 Markdown、代码块和公开链接转换为飞书支持的富文本／卡片。具体消息格式需核对可支持的元素，不能继续把 Markdown 原样塞进普通 `text` 后称为格式保留。
- 表格、数学公式、图表等复杂内容在飞书不能原样呈现时采用可读文本、静态图片或附件回退，保留原内容；不得静默省略。
- 图片和明确附件引用按媒体发送方案交付。本机路径和带行号文件链接在手机上不可直接打开，应转换为可理解的文件信息；只有明确关联的产物才作为附件发送。
- Desktop 专属交互内容，例如代码行评论、diff 审查、跟进按钮、交互式可视化、内嵌浏览器，不能在飞书完整复制。能表达的信息转换为文字／静态产物；操作继续在 Desktop，或在确有需求时另做飞书支持的交互。
- 引用和来源应转为实际可用的来源说明／链接；不能把 Desktop 内部 directive 或引用标记裸露出来当作完整渲染。
- 范围仅包括本桥接请求的最终回复及其明确产物，不自动镜像 Desktop 上独立发起的回合或整个历史。

### 交付与启动形态

保持一个 Go 可执行文件，内嵌 Web 静态资源；本机另外持久保存配置、凭据、SQLite 和附件缓存。用户运行发布产物时不需要单独启动 Node、前端开发服务器、外部数据库或另一个模型服务，但仍需要现有 Codex Desktop 处于可连接状态。

用户所说“exe”泛指可双击程序，不是要求本轮提供 Windows。先交付 Mac 可双击的 Brodge.app，内含核心可执行文件和嵌入的 Web 资源。它是启动入口，不另做嵌入 Web 的应用窗口，也不要求用户打开终端执行命令。

双击程序 → 检查当前 Brodge 实例 → 未运行则启动本机后台／IM／Web → 等管理服务就绪 → 自动打开默认浏览器。已有实例时仅打开现有页面，不启动第二份后台。默认位置不依赖 Finder 的当前工作目录。保留命令行前台入口用于诊断，但不是普通用户必需步骤。

用户明确选择普通浏览器，接受网页不能自行关闭时停留在“Brodge 已退出”。不引入轻量应用窗口或 Electron。暂不需要 launchd 常驻重启／登录自启动；启动入口和后台复用核心程序，关闭后不会被服务管理器自动拉起。

Web 提供“关闭 Brodge”按钮：通过已认证的本机 POST 请求进入退出流程 → 停止接收新请求 → 保存状态并停止桥接／飞书连接 → 释放本机服务与进程资源 → 退出核心进程。页面先显示正在关闭，协调后台完成后显示已退出并尝试 `window.close()`；不强制关闭浏览器其他标签，也不把点击退出请求成功误报为所有资源已关闭。多个 Brodge 页面会同步进入已退出状态。

关闭按钮只退出 Brodge，不停止 Codex Desktop，不强制取消正在运行的 Desktop 回合；下次打开后通过原回合证据恢复结果交付。用户直接关浏览器标签页时后台继续运行，避免长任务因页面关闭被中断。停止 Brodge 后配置、配对、绑定、数据库和附件缓存仍保留。

自动打开 Web 仍保留本机认证边界，启动入口可使用一次性本机登录衔接，不能将长期管理密钥暴露在地址栏或取消管理接口认证。Web 页面本身不会在后台完全退出后重新启动进程；重新启动仍双击程序。

上述 Brodge 更名、Mac 打包和启动／关闭行为已在 S8／S9 实施并记录本机验收，本次范围调整不重做这些功能。当前实现使用 macOS／Unix socket，Windows 不是已交付能力。

## 关键行为与接口

扩展现有来源、绑定和消息数据以表达“入口关联会话、当前绑定、首次创建进度及证据、媒体资源及状态”。保留 `core` 与具体 Desktop／飞书 adapter 的依赖方向，不新增通用 agent 生命周期或独立附件服务。

Web 是本机创建者的管理面，可查看各入口的会话列表和修改当前绑定；IM 的 `/bind`、`/list`、`/switch`、`/current` 只操作发出命令的入口。附件缓存与消息状态重启后仍可恢复。现有 worker 每小时检查，只删除超过 24 小时且 inbox、jobs、outbox 全部没有引用的孤立文件；已完成历史引用也保留，避免追问失去原附件。扫描损坏引用时不删除，不跟随符号链接，不增加用户定时任务。

## 验收与测试策略

- 非创建者私聊／群内 @ 不创建会话、不提交模型、不取得其他入口的绑定；创建者在未允许的群同样不触发。
- 私聊、群 A、群 B 分别绑定；提前手动绑定会跳过自动创建，自动绑定后可通过 Web 或 `/bind` 加入其他已有会话。`/list` 只列本入口，`/current` 对应当前绑定，`/switch` 切换后继续目标会话的历史上下文；不能直接切换到未加入本入口的 ID。
- `/new` 不创建会话、不修改绑定、不转发模型，也不出现在帮助中；保留其他四个命令及 Web 的会话列表和绑定入口。
- 无绑定首次文字／图片／文件消息只创建一个会话，原输入进入首轮。快速两条消息、重复事件、崩溃恢复不重复创建或提交；失败／不确定时保留证据。
- 创建的会话真实出现在现有 Desktop，能在 Desktop 与 IM 继续同一对话，并沿用适用的 Desktop 设置。
- 收图片验证图像内容进入指定会话；收文件验证文件名和原始字节一致、Codex 实际读取内容。模型不支持、下载失败、格式不能处理均有明确反馈。
- 发图片／文件验证原生消息类型、原聊天、文件名和下载字节；覆盖重复发送、上传失败、未知结果和内容被修改后的重试。
- 原配对、当前绑定和历史回合保留；换绑不重定向旧结果。既有文字追问回归继续通过。
- 正常请求只有原消息表情回应和终止后最终答案，长任务无进度消息；回合包含 commentary 与 final 时只发送 final。需要回答或发生错误时能及时提示，不假报完成。
- 覆盖表情 API 失败、重复事件、重启、最终答案超长分段、格式转换及媒体产物；核对信息无丢失，Desktop 专属 directive 不裸露为原始标签。
- 验证模型断流、桥接断连、飞书发送失败三种情况的提示与恢复不会混淆；缺失回合证据不重跑，完成后的重投只使用已保存结果。
- 原生选择／问答核对确切请求、编号映射、选项说明、多题、重复回复、Desktop 已回答、回合结束、重启和未知提交结果；未知 picker 不进入普通答案通道；不新增远程审批流程。
- Mac 双击发布产物无需前端开发服务即启动 IM／Web 并打开浏览器；连续双击只有一个后台实例。按关闭按钮可停止后台并退出，关不了的标签显示已退出；关闭普通标签不影响后台。重新打开不丢数据，不更改 Desktop 配置或重跑既有回合。
- 实现后按仓库约定执行 Go 测试／race／vet、Web 构建和 diff 检查。真实联调仅使用用户明确授权的测试会话与聊天；模拟测试、源码能力和真实闭环分别报告。

## 风险

Desktop IPC 和界面均随版本变化；界面创建可能切换窗口，需要辅助功能权限，并可能受用户同时操作影响。确切新会话 ID、首轮已发送证据及失败后的恢复是本次实现重点，未验证前不能声称自动创建已落地。群图文通过消息内真实 @ 触发；独立图片／文件使用引用回复并 @，现有权限已经实测可取得被引用附件。仅接受同聊天内创建者或当前机器人发出的附件，不按时间合并邻近消息。普通浏览器不保证允许脚本关闭外部打开的标签，用户已接受已退出页面作为回退。

## 未决问题

产品需求已收敛，无项目普通会话与 Web 外观后置均已确认。剩余是技术调查及真实验收条件：

1. 独立 Brodge 的 Desktop 界面创建、准确取得 ID、接续已发送首轮和包含附件的首次输入需验证；不再把受保护 `create_thread` 管道的直接接入作为实施前提。
2. 群里可用的媒体 @／引用形式需用实际事件确认，再给出用户操作说明。
3. 常用异步弹窗的选项与自填答案已真实往返并使原回合继续，按影响回归；其他协议的扩展按最新范围暂不推进。
4. 实现顺序和检查见同目录 `implementation.md`；计划完成后停下，不自动进入编码、改名、换版或安装服务。
